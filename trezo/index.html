ЗадачаThe problem

Trezo — площадка объявлений: люди продают вещи и предлагают услуги, покупатели ищут по категориям и характеристикам и договариваются в чате. Был готовый дизайн 14 экранов, кода не было.

Нужно было с нуля построить API, вместе с frontend-разработчиком перенести дизайн в продакшен и выстроить модерацию так, чтобы объявления проверялись быстро и без ручного разбора каждого.

Trezo is a classifieds site: people sell things and offer services, buyers search by category and attributes and agree on a deal in chat. There was a finished design of 14 screens and no code.

The job was to build the API from scratch, ship the design to production together with the frontend developer, and set up moderation so listings get checked quickly without reviewing each one by hand.

Интересные задачиEngineering highlights

AI

Автомодерация объявленийAutomatic listing moderation

Каждое новое или отредактированное объявление проверяет модель OpenAI: текст, соответствие выбранной категории, адекватность цены с учётом характеристик.

Проверка идёт в фоне, через очередь. Вердикт видно в админке, а спорные случаи уходят модератору в Telegram. Если решение уже принято, устаревший вердикт не отправляется.

Every new or edited listing is checked by an OpenAI model: the text, whether it fits the chosen category, and whether the price makes sense given the attributes.

Screening runs in the background through a queue. The verdict shows up in the admin panel, and questionable cases go to a moderator in Telegram. If a decision has already been made, a stale verdict is not sent.

Реальное времяReal time

Чат без потерянных сообщенийChat that doesn’t lose messages

Сообщения приходят через Mercure (SSE). У каждого диалога свой топик, подписаться на него могут только участники. Сделку фиксируют прямо в диалоге.

После переподключения клиент догружает пропущенное по курсору id, поэтому обрыв сети не теряет сообщения.

Messages arrive over Mercure (SSE). Each conversation has its own topic, and only its participants can subscribe. The deal is closed right in the conversation.

After a reconnect the client catches up from an id cursor, so a dropped connection never loses messages.

КаталогCatalog

Свои характеристики у каждой категорииAttributes per category

У транспорта — пробег и год, у услуг — формат и опыт. Характеристики задаются для категории и подкатегории и наследуются.

Из них же строятся форма объявления, фильтры каталога и подсказки для AI-проверки.

Vehicles have mileage and year, services have format and experience. Attributes are defined per category and subcategory and inherited.

The same attributes drive the listing form, the catalog filters and the hints for AI screening.

Spec-driven

Разработка с AI-агентамиDevelopment with AI agents

Задача сначала описывается спецификацией в OpenSpec: зачем, что меняется, как проверить. Агенты пишут код по правилам проекта.

Результат проходит CI (php-cs-fixer, PHPStan, PHPUnit, ESLint, tsc, Playwright) и отдельных агентов-ревьюеров по качеству и безопасности.

Every task starts as an OpenSpec spec: why, what changes, how to verify it. Agents write code following the project’s rules.

The result goes through CI (php-cs-fixer, PHPStan, PHPUnit, ESLint, tsc, Playwright) and separate reviewer agents for quality and security.

Что я сделалWhat I built

  • Руководство: руководил разработкой, отвечал за серверную часть, помогал начинающему frontend-разработчику: архитектура, ревью, разбор задач.

  • Объявления: дерево категорий с характеристиками, фото в Cloudflare R2, каталог с фильтрами и сортировкой, поиск, избранное, жалобы.
  • Модерация: AI-проверка, модератор в Telegram, повторная модерация после правок.
  • Чат и сделки: переписка в реальном времени, фиксация сделки в диалоге, жалобы на диалоги.
  • Админка: пользователи с блокировкой, объявления, диалоги, журнал аудита, метрики.
  • Инфраструктура: AWS, Docker Compose, Caddy с автоматическим TLS, логи в Elasticsearch и Kibana, алерты об ошибках в Telegram, CI/CD на GitHub Actions.
  • Leadership: led development, owned the backend, mentored a junior frontend developer: architecture, reviews, task breakdown.
  • Accounts: stateless JWT with refresh tokens, sign-up with email verification, password reset, Google sign-in, rate limiting.
  • Listings: a category tree with attributes, photos in Cloudflare R2, a catalog with filters and sorting, search, favorites, reports.
  • Moderation: AI screening, a moderator in Telegram, re-moderation after edits.
  • Chat and deals: real-time messaging, closing the deal in the conversation, conversation reports.
  • Admin panel: users with suspension, listings, conversations, an audit log, metrics.
  • Infrastructure: AWS, Docker Compose, Caddy with automatic TLS, logs in Elasticsearch and Kibana, Telegram error alerts, CI/CD on GitHub Actions.
